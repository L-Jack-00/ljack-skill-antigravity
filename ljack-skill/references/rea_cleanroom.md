# REA(Reverse Engineer Anything) 연계 클린룸 재구축 프로토콜 (Clean-Room Hybrid Rig)

상용/레거시 소프트웨어를 분석하거나 벤치마킹하여 신규 소프트웨어를 제작할 때, 통짜 바이너리를 LLM에 무차별 주입하는 **토큰 폭탄 안티패턴(Full-Dump Anti-Pattern)**을 배제하고, **[타겟팅 핀셋 슬라이싱 ➔ 클린룸 인터페이스 정제 ➔ LJack 런타임 하네스 순방향 재구축]**의 4단계 하이브리드 파이프라인을 강제합니다.

```text
[상용 / 레거시 바이너리 (.exe, .dll, .wasm, .asar)]
                    │
                    ▼ (1단계: REA 핀셋 슬라이싱 / 전체 디컴파일 금지)
   ┌───────────────────────────────────────────────────┐
   │  Ghidra / Frida / REA (rea-sbk) 엔진              │
   │  - 심볼/문자열 검색 기반 타겟 함수만 슬라이싱      │
   │  - AI 컨텍스트에는 오직 핵심 수학식/데이터 규격만 주입 │
   └────────────────────────┬──────────────────────────┘
                            │ (토큰 95% 절약 & 증거 ID 획득)
                            ▼ (2단계: 클린룸 디커플링)
   ┌───────────────────────────────────────────────────┐
   │  클린룸 명세서 (Clean-Room Specification)           │
   │  - 플랫폼 레거시 종속성(Win32, C 포인터) 완전 탈색   │
   │  - 순수 도메인 인터페이스 선언                     │
   └────────────────────────┬──────────────────────────┘
                            │ (순방향 하네스 전환)
                            ▼ (3단계 & 4단계: LJack 런타임 하네스 재구축)
   ┌───────────────────────────────────────────────────┐
   │  LJack Protocol 코어 구현 (기둥 1 ~ 10)            │
   │  - Headless 자체 테스트 러너 우선 작성              │
   │  - 인터랙션 시퀀스 가드 & 픽셀 휘도 감사           │
   │  - 무중단 자가 치유 ➔ 원클릭 GitHub Release 배포   │
   └───────────────────────────────────────────────────┘
```

---

### 1. ❌ 절대 금지: 나이브한 통짜 역공학 안티패턴 (Full-Dump Anti-Pattern)
- 수백 MB짜리 상용 바이너리 전체를 한 번에 디컴파일(Ghidra/IDA)하여 수십만 줄의 의사코드(C/Win32/어셈블리)를 AI 컨텍스트에 쏟아붓지 않는다.
- 이 방식은 **① 수십만 토큰 낭비, ② 심볼 소실(`sub_14001A3F0`)로 인한 AI 환각(Hallucination), ③ 낡은 플랫폼(Win32 GDI 등)의 레거시 관성이 신규 코드베이스에 전염되는 재앙**을 초래한다.

### 2. 🎯 REA 핀셋 슬라이싱 원칙 (Targeted Slicing via REA/rea-sbk)
- REA(Ghidra/Frida/MCP)는 오직 **"순방향으로 유추할 수 없는 단 1~2개의 블랙박스 핵심 부품"**에만 제한적으로 투입한다:
  - *비공개 독자 파일 포맷/바이너리 헤더 구조*
  - *커스텀 암호화/체크섬/인증 토큰 알고리즘*
  - *패키징된 모듈(Electron `.asar`, WebAssembly `.wasm`) 내 핵심 수식*
- 로컬 REA 도구를 통해 심볼/문자열 검색 및 콜 그래프 슬라이싱을 선행하고, AI 컨텍스트에는 오직 **'요약된 수학적 수식/데이터 구조(Evidence ID)'**만 주입하여 토큰을 95% 이상 절약한다.

### 3. 🧼 클린룸 디커플링 (Clean-Room Decoupling)
- 추출된 의사코드의 플랫폼 종속적인 저수준 호출(Win32 API, 저수준 C 포인터 연산)을 그대로 복사하지 않는다.
- 비즈니스 로직의 순수 수학/규격(Clean Specification)만 인터페이스로 추출하고, 구현 계층은 현대적인 대상 프레임워크(Python/PyQt6, Rust, Web Canvas 등)에 맞춰 완전히 새롭게 설계한다.

### 4. 🏗️ LJack 런타임 하네스 순방향 재구축 (Forward Runtime Harness Reconstruction)
- 클린룸 스펙이 확보되면 즉시 LJack Protocol의 순방향 파이프라인으로 전환:
  - **기둥 1**: 코어 도메인과 입출력 UI 완전 분리
  - **기둥 2 & 10**: Headless 자체 테스트 러너 및 인터랙션 시퀀스 가드 우선 구축
  - **기둥 6 & 9**: 물리 입력 안전망 및 픽셀 휘도/알파 무결성 감사
  - **기둥 7**: 배포 아티팩트 청결화, `_internal/` 데이터 격리 및 원클릭 GitHub Release 배포

### 5. ⚖️ 순방향 개발 vs REA 역공학 선택 판정 기준 (Decision Matrix)

| 구분 | 100% 순방향 개발 (LJack 단독) | REA 연계 클린룸 재구축 (하이브리드) |
| :--- | :--- | :--- |
| **적용 대상** | 페인트통(Flood Fill), 스포이드(Eyedropper), 모자이크/블러, HSL 보정, 레이어 합성, 캔버스 리사이즈 등 **컴퓨터 그래픽스/웹 표준 알고리즘이 확립된 기능** | 소스 코드가 유실된 사내 레거시 `.exe` 마이그레이션, 비공개 암호화 세이브 파일/독자 그래픽 포맷 파싱, 모바일/WASM 핵심 토큰 알고리즘 분석 |
| **추천 방식** | 역공학을 배제하고 LJack 런타임 하네스로 즉시 직접 설계 및 자체 테스트 구축 (3배 이상 빠름) | REA로 해당 모듈만 핀셋 슬라이싱 ➔ 클린룸 스펙 도출 ➔ LJack 런타임 하네스로 순방향 재구축 |
| **토큰 효율** | 불필요한 디컴파일 분석이 없어 토큰 소모 최소화 | 전체 덤프 대비 90% 이상 토큰 절약 (타겟 슬라이싱) |
