## 1. 런타임 하네스 엔지니어링 10대 핵심 기둥

하네스(Harness)는 핵심 비즈니스 로직과 UI 시각/인터랙션 계층이 외부의 불확실한 입력, 환경 변화, 렌더링 관성 속에서도 안전하고 예측 가능하게 구동되도록 감싸주는 **실행 및 검증 뼈대(Runtime & Test Rig)**입니다. (모든 기둥은 대상 도메인에 맞게 선택·적용하며, GUI가 없는 순수 CLI/API는 UI 전용 기둥을 생략합니다.)

```text
[외부 세계: 사용자 입력 시퀀스, UI/DOM, 센서, 네트워크 I/O, DB, 렌더링 캔버스, OS 작업표시줄, GitHub API]
           │ (Loose Coupling / 이벤트 델리게이트 / 인터페이스)
┌──────────▼─────────────────────────────────────────────────┐
│              런타임 하네스 코어 (Runtime Harness)           │
│                                                            │
│  1. 코어와 입출력 분리 (Decoupling Core from I/O)           │
│  2. 슈퍼바이저-워커 모델 (Supervisor Loop & Async Worker)   │
│  3. 명시적 FSM 상태 머신 & 블랙보드 컨텍스트               │
│  4. 이벤트 기반 유휴 동결(Pause) & 긴급 비상정지(E-Stop)    │
│  5. 다중 뷰 조작 일관성 & 상태 불변성 (Interaction Invariance)│
│  6. 물리적 입력 자가 치유 & 저수준 훅 인터록 (Input Safety) │
│  7. 릴리즈 청결화, 격리, UX 카피 & 배포 자동화 (CD Rig)     │
│  8. 선제적 맹점 레이더 & 폐루프 타이밍 보정 (Closed-Loop)   │
│  9. [GUI] 비주얼 회귀 & 픽셀 휘도 감사 (Visual & Pixel Rig)│
│ 10. [GUI] 인터랙션 시퀀스 상태 검증 (Event Sequence Rig)    │
└──────────┬─────────────────────────────────────────────────┘
           │ (GUI/네트워크 없이 메모리 상에서 고속 검증, 픽셀 감사 & 이벤트 시퀀스 재현)
[헤드리스 자체 테스트 러너 & 번들링된 린터 스크립트 (Headless Test & Bundled Linters)]
```

- **기둥 1: 코어와 입출력 분리**: 상태/연산/정책은 UI 및 드라이버와 분리하고 이벤트/인터페이스로 테스트 가능하게 설계 (Rust 고성능 코어 + Python 인터페이스 이원화 아키텍처 공식 지원).
- **기둥 2: 슈퍼바이저-워커 모델**: 가벼운 감시 메인 루프와 비차단 비동기 워커 분기 실행.
- **기둥 3: 명시적 FSM & 컨텍스트**: 상태 전이 규칙과 단일 소유권으로 상태 경합 원천 방지.
- **기둥 4: 이벤트 기반 유휴 동결 및 비상정지**: Busy-waiting 루프 대신 OS/스레드 이벤트 대기(`threading.Event.wait`, `asyncio.Event`) 기반 유휴 대기 및 최우선 소프트웨어 비상정지.
- **기둥 5: 다중 뷰 조작 일관성**: 뷰/모드 전환 간 단축키·좌표·스크롤·선택 상태 일관성 보존.
- **기둥 6: 물리적 입력 자가 치유**: 매크로/자동화 등 물리 입력을 점유하는 앱에서 비정상 종료 시 전역 키·마우스 릴리즈 가드 및 OS 훅 바인딩.
- **기둥 7: 릴리즈 청결화, 격리, 독자 중심 UX 카피 & 배포 자동화**:
  - `_internal/` 격리 번들링, 테스트 로그 자동 소거, 배포 요청 시 준비된 Git/GH 자격 증명을 통한 GitHub Release 자동화.
  - **사용자 표면 UX 카피 & 독자 중심 문서화 무결성 가드**:
    1) 최종 UI/릴리즈노트에 '하네스/인터록/FSM/자가치유' 등 개발자 은어 노출 차단 및 사용자 친화적 기능 텍스트 강제.
    2) **주석·README 독자 중심 3불(不) 원칙**: 코드 주석, docstring, README에서 '나만 아는 변경 이력(vX.X 버그 수정 등)', '임시 땜질성 코멘트', '작업 일지/약어'를 배제하고, 처음 읽는 협업자를 위해 **현재 기능의 목적(Why)과 시스템 불변식(Invariant)** 관점으로 영속적 기술.
- **기둥 8: 선제적 맹점 레이더 & 폐루프 타이밍**: 실시간 루프/정밀 타이머 앱에서는 OS 타이머 오차 드리프트를 감산 보정하고, 완료 시 잠재 맹점을 사전 보고.
- **기둥 9: [GUI] 비주얼 회귀 & 픽셀 휘도 감사**: 오프스크린 캡처(PNG/ICO)로 다크/라이트 테마 1px 고휘도 테두리 및 모서리 투명도 검출.
- **기둥 10: [GUI] 인터랙션 시퀀스 상태 검증**: 호버-드래그-팝업닫기-외부클릭 등 연속 조작 시퀀스 헤드리스 재현.

## 2. 자율 에이전트 11대 실행 강령 (Autonomous Directives)

1. **버전 독립성 절대 준수**: 스킬 버전(v7.5.0)과 프로젝트 고유 버전(v1.0.0 등)을 엄격히 분리한다.
2. **완료 조건은 '사용자 응답'이 아니라 '자체 검증 ALL PASS'다**: 자체 테스트 러너 및 린터가 모두 통과하여 결함 0건이 될 때까지 기술 문제를 자율 완주한다.
3. **무중단 자가 치유 루프 (Self-Healing Loop)**: 컴파일/테스트/린트 실패 시 사용자에게 묻지 않고 스택 트레이스를 역추적하여 스스로 수정을 반복한다.
4. **마이크로 디시전 자율화**: 변수명, 내부 함수 구조, UI 여백 등 개발 상식선의 사안은 에이전트가 직접 결정한다.
5. **승인 관문 및 최소 개입 (Approval Gate)**: 착수 후 기술 작업은 자율 완주하며, 기획 상충, 외부 자격 증명 입력, 또는 외부 공개 릴리즈 승인 시에만 사용자 응답을 요구한다.
6. **물리적 입력 자가 치유 및 세션 바인딩**: 전역 입력 점유 앱에서 비정상 종료 시 물리적 입력을 강제 해제하고 비동기 세션을 타깃 바인딩한다.
7. **배포 패키징 청결도, 데이터 격리 및 릴리즈 완결**: `_internal/` 격리 및 아티팩트 청결화를 기본 수행하며, 사용자가 GitHub 릴리즈 배포를 요청하고 자격 증명이 유효한 경우 릴리즈 업로드까지 완결한다.
8. **선제적 맹점 발굴 및 사전 보고 강제**: 완료 보고 시 `[🔭 시니어 아키텍트 관점의 잠재 맹점 / 개선 레이더]` 섹션을 의무 보고한다.
9. **비주얼 에셋 톤앤매너 사전 고정 및 알파 무결성 검증**: GUI/아이콘 제작 시 시각 규격을 고정하고 모서리 투명 알파 및 테두리 휘도를 검증한다.
10. **QA 결함의 회귀 테스트 승격 및 인코딩 안전망**: 수정된 결함(BUG-ID)은 회귀 테스트로 영구 등록하며, CLI/콘솔 입출력에 UTF-8 안전 가드를 탑재한다.
11. **사용자 표면 UX 카피 & 독자 중심 문서화 무결성 감시 가동**:
    - **UI 표면**: UI 레이블, 창 제목, 메뉴, 툴팁, 팝업, 릴리즈 노트에서 '하네스/인터록/FSM/자가치유/AI' 등 내부 구현 용어를 검출하여 사용자 기능 중심 언어로 치환한다.
    - **주석 및 README 독자 중심 클린화**: 코드 주석, docstring, README에서 'vX.X 버그 수정', '임시 땜질', '기존 코드 교체', '나만 아는 약어/작업 일지' 등 시점 의존적 메모(Temporal Notes)를 배제하고, 기능의 목적(Why)과 시스템 불변식(Invariant) 중심의 영속적 기술을 의무화한다.

## 3. 개발자-AI 페어 프로그래밍 7대 마법의 검증 질문 (질문 프레이밍)

1. **맹점 발굴**: *"시니어 시스템 엔지니어 입장에서 내가 배경지식이 없어 놓친 OS/하드웨어 레벨의 맹점(Unknown Unknowns)이나 안티패턴 3가지를 짚어줘."*
2. **부하/내구성 검증**: *"이 코드가 장기 실행 환경이나 대량 연속 요청, 극단적인 부하를 받으면 가장 먼저 터질 메모리 누수나 병목이 어디야?"*
3. **아키텍처 비판**: *"이 구현을 시니어 아키텍트 관점의 악마의 대변인(Devil's Advocate) 입장에서 비판해줘."*
4. **비주얼/UI 완성도 검증**: *"다크모드/고대비 모드나 다양한 DPI 해상도 환경에서 1px이라도 튀거나 어색해 보이는 네이티브 스타일 잔재나 모서리 알파 결함이 없는지 점검해줘."*
5. **인터랙션/시퀀스 조작 검증**: *"사용자가 마우스를 빠르게 호버-드래그하거나 팝업을 닫고 클릭하는 등의 불규칙한 조작 시퀀스나 단축키 충돌에서 터질 수 있는 엣지 케이스를 점검해줘."*
6. **클린룸/역공학 경계 검증**: *"이 구현에서 외부 바이너리나 상용 프로그램을 역공학(REA)해야 할 비공개 독자 부품이 있는가, 아니면 표준 알고리즘 기반으로 순방향 구현하는 것이 속도와 유지보수 면에서 유리한가?"*
7. **UX 카피 및 독자 중심 문서화 검증**: *"이 프로그램의 윈도우 제목, 메뉴, 툴팁, 안내 팝업뿐 아니라 코드 주석과 README에 'vX.X 버그 수정', '임시 땜질', 'AI 생성 코드'처럼 제3자가 보았을 때 맥락을 알 수 없는 과거 변경점 위주의 텍스트가 남아있지 않은가? 처음 프로젝트를 접한 협업자나 사용자가 보아도 목적(Why)과 기능(What)을 즉시 이해할 수 있는 독자 중심 문서로 다듬어졌는지 점검해줘."*

## 4. 자율 실행 5단계 표준 파이프라인

```text
[1단계: 요구사항 승인, 버전 분리 및 빠른 하네스 스캐폴딩]
  - 프로젝트 고유 버전 명시, scripts/harness_scaffolder.py 호출로 표준 골격 즉시 생성
       ↓
[2단계: Headless 테스트 러너 및 GUI 검증(해당 시) 구축]
  - 메모리 상에서 코어 로직을 고속 검증하는 테스트 스위트 (및 UI 시퀀스 테스트) 작성
       ↓
[3단계: 비즈니스 로직 및 런타임 하네스 구현]
  - 느슨한 결합, 비동기 워커 분기, 이벤트 기반 유휴 대기(Pause), 안전 가드 탑재
       ↓
[4단계: 자가 치유 루프 및 다중 정적/품질 감사]
  - 자체 테스트 ➔ (GUI 시) 픽셀/인터랙션 검증 ➔ scripts/harness_doctor.py 채점 ➔ scripts/ux_copy_linter.py 감사
  - ❌ 실패 시: 결함 진단 / 스택 트레이스 역추적 ➔ 코드 수정 ➔ 재검증 (자율 반복)
```
